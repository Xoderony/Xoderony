# 移除开放泛型与构建时自动集合方案

状态：已实施，2026-09-14。41 项 Release 契约测试通过，12 项目标基准完成。现行用法与契约已同步至 [容器设计](di-container.md) 和 README，性能及构建成本见 [实施结果](../../benchmarks/results/di-build-time-collections.md)。以下保留确认的设计与取舍。

## 用户确定的方向

- 去掉开放泛型注册。
- 集合来自普通服务注册，内部根据服务数量在 Build 时自动追加集合注册。
- 外部不能手动注册内部用于集合解析的类型。
- 集合引用原始注册实例，不引入独立元素所有权。

## 术语

- 服务组：按完整服务类型与 Key 收集的可见注册；本层同键组整组替换父层，不合并。
- 自动集合注册：Build 根据服务组添加的解析入口；追加映射不等于立即创建元素。
- 保留集合类型：T[]、IEnumerable<T>、IReadOnlyList<T>，外部不能将其注册为服务，包含实例默认类型、工厂声明类型与 As 别名。具体 List<T> 不属于保留形式。
- 闭合泛型类型：如 Repository<int>，不同于开放定义 Repository<>；继续作为普通完整 Type 注册，不再按泛型定义划分服务族。

## 当前实现与新方向的差异

当前 RegistrationBuilder 显式保存 AsCollection 成员关系；Container 分别保存单个、闭合泛型、开放单个模板、集合缓存和开放集合模板。当前同层单个服务类型与 Key 重复会报错。

新的数量驱动集合允许多个实现暴露同一服务与 Key，单个解析存在多个候选时报告歧义。移除开放泛型后，不再需要运行时闭合模板及其缓存；闭合泛型按普通 Type 对待，取消普通/泛型两路和泛型服务族判重。AsCollection 成员声明由 Build 自动收集替代。

## 第一轮已确认

1. 至少一条注册就生成集合，保持集合消费方在实现数量减少时仍可工作。
2. 多条注册时 Resolve<T> 报告歧义，不隐式选择最后一项；Build 允许服务组存在。

## 第二轮已确认

1. 保留 T[]、IEnumerable<T>、IReadOnlyList<T> 三种解析形式，并禁止外部直接注册这些服务类型。保留 T[] 同时禁止直接注册配置数组，需要包装对象；具体 List<T> 仍可作为普通服务。
2. 父层服务组为 [A,B]、子层同服务与 Key 注册 C 时，子层可见组为 [C]，父层仍为 [A,B]。闭合泛型与普通类型统一采用完整 Type 判定，不再保留泛型服务族跨层限制。

## 第三轮已确认

1. 零条注册时视为未注册：Resolve 抛错、TryResolve 返回 false、IsRegistered 返回 false，不在解析时补空集合。可选模块需要通过 TryResolve 处理，不能直接注入不存在的集合。
2. 拒绝本层相同声明类型与 Key 重复，允许不同实现共同暴露相同服务类型。类型注册按实现类型、实例按实际类型、工厂按 RegisterFactory<T> 的声明 T 检查；不提前执行工厂推断真实实现。检查跨这三种来源统一进行，但只限本层；父子层允许按服务组覆盖，兄弟层独立。

## 沿用的解析与所有权契约

- IsRegistered 查询注册可见性，不校验依赖图；多候选服务仍返回 true，不求值任何候选。
- TryResolve 仅对目标缺失返回 false；存在多个候选时与 Resolve 一样抛出 InvalidOperationException，不能将歧义当成缺失。
- 单个解析发现歧义时，不尝试创建任何候选；Build 不因服务组多候选而失败。
- 集合按注册顺序首次求值，IEnumerable<T> 与 IReadOnlyList<T> 共享同一个不可修改的集合结果；T[] 每次返回副本。元素引用保持共享。
- 构造、工厂和集合求值失败继续缓存、不重试；集合失败前已创建的元素仍归原注册容器释放。
- 同一条注册通过多个 As 别名暴露时共享一个原始 Lazy，同一别名重复添加去重。AsSelf 与 AsImplementedInterfaces 保留原有单个别名语义；后者遇到保留集合接口也会被拒绝，不静默跳过。
- 每条注册的所有别名使用同一个 Key；集合按同服务与 Key 分组，不跨 Key 收集。
- 外部已有实例不自动注入或释放；类型/工厂结果由原注册容器拥有。子层继承实例及集合元素不重复登记释放。

## 实施时需保持的边界

- 集合从最终可见服务组生成；子层替换元素组时，不得留下父层旧的自动集合映射。
- 自动集合生成只遍历原始服务组，不递归为新生成的集合入口继续生成集合。
- 保留运行时完整 Type 注册与现有工厂入口；不把移除开放泛型解释为禁止所有泛型类型。
- Build 追加映射不提前创建服务，实例所有权仍归原注册容器。
- 保留类型校验覆盖注册声明类型及显式服务别名，按类型结构精确识别 T[]、IEnumerable<T>、IReadOnlyList<T>，不把 List<T> 等实现了集合接口的具体类型全部禁止。工厂按声明 T 校验，不为检查返回类型提前执行工厂。
- IResolver 继续固定为本层容器；其自动集合也必须反映本层 IResolver，而不是继承父层对象。

## 已实现的构建与解析流程

1. 注册阶段拒绝含未绑定泛型参数的类型，以及保留集合类型；记录普通别名、来源与 Key。删除 AsCollection 和开放泛型映射逻辑。
2. Build 检查本层 (声明类型, Key) 重复。为每条注册建立一个原始 Lazy，按 (完整服务类型, Key) 暂时收集引用列表。
3. 对每个非空本层服务组生成单个入口和三个集合入口。单候选直接使用原始 Lazy；多候选的单个入口报告歧义，不求值元素。三个集合入口共享集合创建状态，数组入口返回副本。
4. 本层四种入口整组替换父层对应入口，未覆盖服务沿用父层映射与原始实例所有权。可以先生成完整本层映射，再用 TryAdd 继承父层，避免残留父层旧集合。生成时只枚举本层原始服务组。
5. 解析根据完整请求 Type 与 Key 查找已建立的入口；不执行开放泛型匹配、泛型闭合或自动补注册。缺失与歧义按上述契约处理。

运行时注册映射固定，使用一张 Dictionary<(Type, int), Lazy<object>>，不再需要泛型展开缓存和独立集合模板表。多候选单个入口使用只抛歧义异常的 Lazy；三个集合入口共用只读结果 Lazy，ResolveCore 一次查询后仅对数组复制结果。未添加额外入口包装类型。

## 相比当前实现的变更清单

- 删除 OpenGenericRegistration、开放单个及集合模板、闭合请求展开流程、泛型服务族祖先检查。
- 删除 AsCollection、集合成员类型列表；同服务不同实现通过普通 As 自然组成组。
- 保留闭合泛型与运行时完整 Type 注册，普通/泛型查找统一。
- 用本层声明类型判重替代同服务类型判重；新增单个解析歧义结果。
- Build 为所有非空原始服务组追加三种集合入口，外部不再能显式注册空集合或保留集合服务。
- 迁移涉及开放泛型、AsCollection、手动集合注册和重复工厂声明的测试、基准与文档。外部项目的迁移不自动纳入本轮实施范围。

## 验证方向

已验证：零/一/多候选、Resolve/TryResolve/IsRegistered、别名去重、声明类型跨来源重复、相同实现不同 Key、闭合泛型、保留类型校验、父子组替换及 IResolver、集合与单个共享实例、失败缓存与释放。歧义检测不创建候选。

性能同时测单个命中、只读集合命中、数组副本、Build 与子层构建成本。自动为每个别名创建集合会增加映射数量及首次构建分配；移除开放泛型会减少运行时状态，但不能据此预先承诺整体更快或更省内存。旧开放泛型基准需移除或改为显式闭合注册，并标明语义变化，不做不等价的前后比较。
