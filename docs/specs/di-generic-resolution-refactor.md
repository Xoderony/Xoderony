# 普通服务与泛型服务分路及缓存调整方案

状态：历史方案。后续已采用服务族层级约束和显式 AsCollection 成员关系；当前单个注册不再保存整组 Lazy，集合引用同一条普通注册，见 [现行容器契约](di-container.md)。下文保留初版及中间版本的设计记录，不作为当前实现要求。

## 后续修订：泛型服务族只归属一个注册层级

同一 `(泛型服务定义, Key)` 只能在父子链中的一个层级注册。同层允许多条，兄弟容器互不限制，普通服务仍允许子层覆盖。判重按暴露的服务类型，开放与闭合类型统一到泛型定义；不同闭合参数也不能在同 Key 下分层注册。

Container 构建时从父层可见的开放表与闭合表收集服务族，使用临时 HashSet 检查本层声明，冲突抛出 ArgumentException。没有本层注册时无需建立检查集合。检查不求值服务或执行工厂，失败不会执行构建回调。

这项契约使父层展开缓存可以安全继承：闭合表改为直接保存 List<Lazy<object>>，删除 GenericRegistrationGroup 及 IsExpansion。整组延迟求值、失败缓存和原注册所有权保留；若父层在子层创建后才预热，子层可自行展开，底层实例仍共享。同层精确闭合优先于开放；原先允许父层精确与子层开放竞争的规则不再适用。

下面内容是初版方案的历史记录，其中来源标记、跳过父层展开缓存、泛型跨层覆盖及 36 项测试记录均已被本节替代。[初版性能报告](../../benchmarks/results/di-generic-routing.md) 未重新测量本次简化后的实现。

## 问题与目标

调整前普通单例缓存约 8 ns；混合闭合泛型请求约 24–29 ns，两者均为 0 B。泛型命中先尝试普通注册表，再匹配开放泛型定义，最后查询注册内部的实例缓存。证据见 [此前复测](../../benchmarks/results/di-container-comparison.md#最新缓存复测)。

目标：

- 按完整请求类型提前分为普通服务与泛型服务两个解析路径。
- 泛型稳定命中：一次类型分类、一次以完整闭合服务类型和 Key 为键的字典查询、取最后一个 Lazy 的 Value。
- 命中时不调用 GetGenericTypeDefinition、GetGenericArguments、MakeGenericType，不查询开放模板或注册内部缓存。
- 不把所有服务再叠加到一张统一解析缓存；普通服务仍直接使用原有注册组。
- 不改变公共 API、匹配范围、首次报错时机、实例所有权和集合契约；泛型约束失败改为缓存、不重试，已获用户确认。
- 不承诺绝对纳秒目标；同时测量普通分支新增类型判断的代价，以及首次展开的分配成本。

这里的“两条路径”不等于“必须只有两个 Dictionary”。开放定义是未命中时需要的注册来源；若强求与闭合缓存共用同一种值，会引入不同状态的表示和判断。

## 术语与已确定边界

| 名称 | 含义 |
|---|---|
| 普通服务类型 | 不满足 IsConstructedGenericType 的有效闭合请求类型；包括数组类型，数组再走集合后备逻辑。 |
| 闭合泛型服务 | 例如 IRepository<int>，无论由类型、实例还是工厂提供，都进入泛型路径。 |
| 显式闭合注册 | 构建时即声明提供一个具体闭合服务类型；只匹配该类型。 |
| 开放注册 | 例如 IRepository<> → Repository<>，在未命中时按具体类型参数展开。 |
| 展开缓存 | 从当前容器可见开放注册组派生的闭合请求结果，不是新的显式注册。 |
| 注册所有者 | 决定创建时使用哪个容器解析依赖、由谁释放结果的原始注册容器。 |
| 请求缓存所属容器 | 决定本次请求选中哪组注册的容器；可以不同于实例的注册所有者。 |

“闭合与开放都纳入泛型路径”只统一处理位置，不统一匹配范围。例如 Register<Repository<int>>() 不产生 Repository<string> 注册。

分流依据必须是暴露的服务类型，不是实现类型。例如非泛型 SpecialRepository 可以提供 IRepository<int>；一个 Repository<int> 实例可以同时提供非泛型 IDisposable 和泛型 IRepository<int>，两个路径必须共享同一个原始 Lazy。

## 推荐存储结构

以下名称用于方案说明，实施时沿用项目命名风格，不要求增加公开类型：

1. 普通注册表：完整普通服务类型 + Key → List<Lazy<object>>。
2. 闭合泛型表：完整闭合服务类型 + Key → 泛型注册组。
3. 开放模板表：开放服务定义 + Key → List<OpenGenericRegistration>。

泛型注册组建议使用小型内部结构体，保存：

- List<Lazy<object>>：单个解析与集合解析使用的组；
- IsExpansion：是否来自开放注册的展开，仅用于构建、继承和检查，不进入命中路径的条件判断。

这不是按泛型定义分桶：闭合请求直接命中第 2 张表。泛型定义只用于未命中后查询第 3 张表。

相较当前实现，新增一张闭合泛型表，将原普通表中的显式闭合泛型条目迁过去，再填入运行时展开结果。没有复制整张普通注册表，也不新增所有服务共用的解析缓存。

OpenGenericRegistration 继续保存原始闭合实例 Lazy，承担跨别名、父子容器的实例共享与创建状态。它只在展开槽位首次求值时使用，不参与稳定命中路径。暂不顺带删除其中的已有缓存优化。

## 注册与 Build

1. 普通类型/实例/工厂注册先建立一个原始 Lazy，再按每个服务别名的类型分流；不能按别名重复创建 Lazy。
2. 开放实现注册仍建立一个 OpenGenericRegistration，所有开放服务别名引用同一个注册对象。
3. 显式闭合泛型组以 IsExpansion=false 放入闭合泛型表。多条同键本层注册按原顺序组成一组。
4. 普通组、显式闭合泛型组、开放组分别按原规则合并父层：本层同键存在则覆盖父层整组。
5. 继承父层闭合泛型表时，仅复制 IsExpansion=false 的组，跳过所有展开缓存。
6. 保留每层无键 IResolver 为自身的现有处理。
7. 不保留可变 RegistrationBuilder 引用；重复 Build 仍建立独立的本层创建状态。

反例必须保持正确：

- 父层仅注册开放 IRepository<> 并预热 IRepository<int>，子层重新注册开放 IRepository<>：子层使用自己的开放注册，不能继承父层展开缓存作为显式闭合项。
- 父层显式注册 IRepository<int>，子层仅注册开放 IRepository<>：父层精确注册依然优先，即使子层更近。
- 子层继承开放注册但不覆盖：子层重新建立请求缓存，底层仍共享父层注册的 Lazy，依赖解析与释放归父层。

## 单个服务解析

示意代码表达实际实现的顺序：

~~~csharp
if (serviceType.IsConstructedGenericType) {
    if (_genericRegistrations.TryGetValue((serviceType, key), out var group)) {
        return group.Instances[^1].Value;
    }
    // 查开放定义；若匹配，建立本容器的展开组，发布到缓存后再求值。
    // 若无注册，再考虑泛型集合后备；最后返回缺失。
} else {
    if (_registrations.TryGetValue((serviceType, key), out var group)) {
        return group[^1].Value;
    }
    // 数组进入集合后备；其他返回缺失。
}
~~~

命中分支不判断来源标记，不先获取泛型定义，不调用 OpenGenericRegistration。

Resolve 和 TryResolve 共用这一核心。TryResolve 仍只对目标缺失返回 false，不吞掉构造、注入、泛型约束或工厂异常。

## 已确定：展开注册组的粒度

用户选择：首次请求建立完整的轻量 Lazy 槽位组，但只求值本次需要的槽位，接受首次展开的额外槽位分配。

- 每个槽位的工厂保存 serviceType 和对应 OpenGenericRegistration，首次求值再调用其 GetOrCreateInstance。
- 先把完整组加入当前容器缓存，再对最后一项取 Value。
- 创建槽位时不执行 MakeGenericType，不创建服务，不解析依赖。
- 非最后一项保持未求值；集合请求再逐项求值。
- 显式闭合注册直接使用原有 Lazy，不额外包装。
- 开放展开会多一层请求槽位 Lazy；其首次求值转发到注册所有者的实例 Lazy。稳定命中只读取外层已缓存的 Value。
- 请求槽位不负责 Dispose，也不把结果再次登记到当前容器的释放列表；释放只发生在原始创建流程。

为什么不能直接遍历全部模板取得闭合 Lazy：当前 GetOrCreateInstance 会创建实例，即使改回返回 Lazy，泛型闭合本身也可能抛约束异常。为了缓存整组而提前闭合所有注册，会改变单个解析的失败时机。

必须保留的场景：先注册仅允许 struct 的实现，再注册无约束实现；请求引用类型的单个服务应成功选中最后一项。不能因为前一项约束失败而阻止单个解析；请求集合时才会遇到前一项失败。

代价：首次展开会分配整组外层 Lazy、捕获状态及组存储，即使之后只使用最后一项。每个闭合服务别名、每层实际请求缓存都可能产生槽位，但原始实例仍共享。

未采用：只缓存最后一项、集合继续查询原始组。它首次单个请求分配较少，但单个与集合要维护不同的缓存/来源访问方式，不能把单项缓存当成完整集合。

## 已确定：统一缓存失败

OpenGenericRegistration 在建立原始 Lazy 之前执行 MakeGenericType；调整前泛型约束失败后，后续请求会再次尝试闭合。现在整组外层 Lazy 槽位缓存 GetOrCreateInstance 抛出的约束异常。

用户接受统一缓存该闭合请求的失败：首次报错时机和异常种类不变，后续直接重抛同一个异常，不重新闭合。异常对象身份与重复检查行为相对旧实现有变化，已在测试和现行规格中记录，不能称作完全无行为变化的缓存重构。

约束失败按请求槽位缓存，不承诺不同服务别名之间共享同一个约束异常对象。进入原始实例 Lazy 后的构造、注入失败仍由原始注册共享。失败不回退到其他注册；不同闭合类型不因彼此失败而失效。

## 集合、可见性和异常

- 明确注册的集合仍优先：IEnumerable<T>/IReadOnlyList<T> 经泛型表匹配，T[] 经普通表匹配。明确的开放 IEnumerable<> 注册也应先于自动集合后备。
- 自动集合不把结果数组缓存为服务注册；每次仍生成结果数组，元素共享实例。
- 查集合元素组时按元素服务类型分流，不能让普通/泛型入口互相跳过明确注册。
- 已缓存的单个解析不能截断集合；多注册顺序、同 Key 筛选、子层整组覆盖不变。
- IsRegistered 只检查注册可见性，不触发展开、创建或泛型约束校验，不把自动集合能力变成显式注册。
- 不缓存“缺失”为实例槽位，不将自动集合结果写进闭合泛型表，避免 IsRegistered 随调用历史变化。
- 原始 Lazy 的失败缓存和循环创建检查保留。推荐槽位方案会额外缓存该请求槽位的失败；它不允许重试或回退到较低优先级注册。
- 泛型约束失败仍在实际求值所选槽位时发生。异常不额外包装，不添加专门恢复流程。
- 发布缓存组前不执行用户代码。求值前结束所有 CollectionsMarshal ref 的使用，防止递归解析导致扩容后引用失效。
- Dispose 清空新增闭合泛型表；不会额外释放槽位返回的实例。

## 实施范围与顺序

以下清单已完成；用户在确认取舍后授权实施。

1. 按已确定的整组槽位与统一失败缓存规则补充回归测试。
2. 调整 Container 构建过程，按服务别名类型分流并区分显式组与展开组。
3. 调整 ResolveCore、集合元素组查找及 IsRegistered，保留统一缺失/异常契约。
4. 实现泛型未命中时的组展开，保留原始 OpenGenericRegistration 所有权与别名缓存。
5. 检查 Dispose 和子作用域继承；不顺带调整成员注入、工厂 API 或并发模型。
6. 运行目标项目测试及同机前后基准；依据结果保留或撤回，再同步现行规格和 README 中受影响的说明。

实际修改涉及 Container、内部 GenericRegistrationGroup 结构体、目标测试、基准和文档；OpenGenericRegistration 无功能修改。范围是注册/解析/继承的局部结构调整。

## 验证要求

行为回归：

- 非泛型实现提供泛型接口；同一注册跨普通/泛型服务别名共享实例与释放一次。
- 闭合类型注册、闭合实例注册、闭合工厂注册均保持精确匹配，不扩展到其他类型参数。
- 显式闭合项优先于开放项，包括父层精确与子层开放的组合。
- 父层预热在创建子层之前/之后，结果不变；子层覆盖与父层所有权正确。
- 同一个实现的多个泛型别名、不同 Key、不同闭合参数的共享/隔离正确。
- 单个先于集合、集合先于单个、多注册顺序不变；较早注册约束失败不影响最后一项的单个解析。
- 泛型构造失败、跨别名递归创建、缺失目标和 TryResolve 的行为正确；重复解析同一个约束失败槽位重抛已缓存异常，其他闭合类型仍可正常解析。
- 显式数组/泛型集合、自动空集合和 IsRegistered 的语义不随预热变化。

性能与成本：

- 保留本次最新缓存复测为基线，普通/泛型分别测量。
- 混合四种运行时闭合类型，预热后每次仍为 0 B；追加泛型接口别名与 Key 场景。
- 不以静态 typeof 单一查询或 Jab 的生成代码数据代表动态泛型请求。
- 测 Build、首次展开及第二个别名首次请求；多注册组需测只请求最后一项的首次分配。
- 检查多个作用域的缓存驻留成本，说明条目/槽位增长方式，不只看单次 Resolve 的数字。
- 接受条件：契约测试通过、命中保持零分配、泛型改进超过测量噪声、普通路径与首次展开的回退成本被明确报告。
- 是否值得采用由实测与复杂度共同判断；尚未承诺具体倍率或通过阈值。
